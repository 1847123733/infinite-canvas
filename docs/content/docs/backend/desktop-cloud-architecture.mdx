# 桌面版云端架构方案

本文档用于约定 `infinite-canvas` Electron 桌面版与 `vben-admin-monorepo-template` 云端系统之间的新架构边界，目标是把账号、权限、模型配置、OSS 配置、生成记录和日志统一收敛到云端，同时保留桌面版本地画布与 Go 图片生成执行能力。

## 背景与目标

当前桌面版具备本地 Go 后端、Next.js 前端和 SQLite 数据库，适合本地创作，但账号体系、生成审计和云端统一控制能力不足。现计划接入 `D:\work\Ai\vben-admin-monorepo-template`，由其 Vue3 + Python + PostgreSQL 架构作为唯一云端权威中心，统一控制桌面版账号登录与生成权限。

本次改造目标：

- 使用 `vben-admin-monorepo-template` 作为桌面版唯一单点登录中心。
- 桌面版改为强在线模式，启动时必须连接云端校验会话。
- 云端账号被禁用后，桌面版不能继续发起生成请求，只能查看本地已存在的画布和生成结果。
- 图片生成仍由桌面版 Go 执行，不改成云端 Python 代生成。
- 模型配置和 OSS 配置由云端下发，桌面版不长期持有敏感配置。
- 云端按账号保存最终生成图片、生成记录和执行日志，供后台查询。
- 当前阶段不接入算力点体系。

## 已确认决策

以下决策已明确，不再作为开放问题：

- 云端 PostgreSQL + Python 为账号、配置、记录和日志的唯一权威来源。
- 桌面版采用强在线模式，云端不可用时只能进入只读态。
- 图片生成继续由桌面版 Go 执行。
- 模型 `Base URL`、`API Key`、模型名等配置由云端下发。
- 每次点击生成前，必须先向云端申请一次生成授权票据。
- 生成图片上传 OSS 的目标路径固定为：

```text
daily_orange_ai/infinite_canvas/{user_id}/{yyyy}{mm}{dd}/{random}.{ext}
```

- 云端后台当前只需要查看最终成品图，不要求存储全过程中间图。
- `prompt` 需要拆成两份保存：
  - `user_prompt`：用户直接输入的内容。
  - `final_prompt`：系统组装后实际发送给模型的完整内容。

## 总体架构

系统改造后分为四个明确边界：

### 1. vben-admin-monorepo-template 云端

由 Python 后端和 PostgreSQL 负责：

- 账号登录和单点登录。
- 桌面版会话管理。
- 用户状态、角色和桌面版准入权限判断。
- 模型配置管理。
- OSS 配置管理。
- 生成授权票据签发。
- 生成任务记录和日志记录。
- 后台按用户查看桌面版最终生成图片。

### 2. Electron + Next.js 桌面前端

负责：

- 登录界面和会话状态维护。
- 画布、本地素材、历史结果展示。
- 强在线校验和只读模式切换。
- 用户点击生成时向云端申请生成票据。
- 将票据传给本地 Go 执行层。

### 3. Go 本地执行层

负责：

- 用云端票据换取本次生成快照。
- 调用上游模型执行图片生成。
- 将最终图片上传到 OSS。
- 把生成完成结果和过程日志回传云端。

### 4. 本地存储

本地继续保留：

- 画布项目。
- 浏览器本地图片/视频/音频缓存。
- 桌面端只读浏览所需的本地结果。

本地不再作为以下内容的权威来源：

- 账号状态。
- 模型配置。
- OSS 配置。
- 云端生成任务记录。
- 云端审计日志。

## 登录与会话设计

### 登录入口

桌面版登录不再使用本地 Go `/api/auth/login` 作为主入口，而是改为直接对接云端 Python 桌面专用登录接口。

### 登录流程

1. Electron 打开登录页。
2. 用户输入云端账号密码。
3. 桌面端请求云端登录接口。
4. 云端校验 `system_users.status`、`system_roles.can_login_infinite_canvas`、`is_super_admin`。
5. 登录通过后返回：
   - `access_token`
   - `refresh_token`
   - `user`
   - `desktop_session_id`
6. 桌面端保存会话，进入在线可生成态。

### 强在线要求

每次桌面版启动时必须先请求云端 `me` 或 `session-status` 接口：

- 校验成功：允许进入可生成态。
- 校验失败：进入只读态。
- 云端不可用：进入只读态。
- 账号禁用：进入只读态。

### 只读模式

只读模式下允许：

- 查看本地无限画布。
- 查看本地已生成图片。
- 查看本地历史记录。
- 导出本地项目。

只读模式下禁止：

- 发起图片生成。
- 请求生成快照。
- 上传新图片到 OSS。
- 修改云端相关生成配置。

## 生成授权票据与快照设计

### 票据设计原则

每次点击生成都必须重新申请一次票据，票据应该具备以下特征：

- 短时有效，例如 60 秒。
- 一次性使用。
- 与用户、桌面会话、模型、能力绑定。
- 过期或已使用后不可重放。

### 票据申请流程

1. 桌面前端点击生成。
2. 前端请求云端 `generation-tickets`。
3. 云端检查：
   - 用户是否在线。
   - 账号是否未禁用。
   - 角色是否允许使用桌面版。
   - 当前模型是否允许使用。
4. 云端创建任务和票据，返回：
   - `ticket_id`
   - `task_id`
   - `expires_at`

### 快照设计原则

Go 不长期保存模型和 OSS 敏感配置，每次生成前使用 `ticket_id` 向云端换取一次本次生成快照。

快照应只包含本次生成所需的最小字段：

- `task_id`
- `user_id`
- `provider`
- `model`
- `base_url`
- `api_key`
- `oss.endpoint`
- `oss.bucket_name`
- `oss.access_key_id`
- `oss.access_key_secret`
- `oss.object_key`
- `expires_at`

其中：

```text
oss.object_key = {targetPath}infinite_canvas/{user_id}/{yyyy}{mm}{dd}/{random}.{ext}
```

其中 `targetPath` 复用管理端现有 `system_settings.oss_config.targetPath`，云端会先规范化为“去掉前导 `/`、保证尾部 `/`”，再拼接固定子路径。桌面版不单独配置 `region`，由 OSS `endpoint` 推导；也不单独配置启用开关，是否可用由 OSS 关键字段是否完整决定。

## OSS 路径规则

### 目标路径

Go 上传最终图片时，object key 规则固定为：

```text
{targetPath}infinite_canvas/{user_id}/{yyyy}{mm}{dd}/{random}.{ext}
```

当管理端 `targetPath = daily_orange_ai/` 时，实际示例为：

```text
daily_orange_ai/infinite_canvas/10086/20260612/7c3f2e9a.png
```

### 记录格式

云端数据库中建议同时保存：

- `result_bucket`
- `result_object_key`
- `result_oss_url`
- `result_public_url`

其中 `result_oss_url` 格式为：

```text
oss://decent-lancheng/daily_orange_ai/infinite_canvas/{user_id}/{yyyy}{mm}{dd}/{random}.{ext}
```

## 管理端 OSS 配置流程

桌面版云端生图继续复用现有 `system_settings.oss_config`，不拆新设置 key。

根级字段继续保留：

- `accessKeyId`
- `accessKeySecret`
- `endpoint`
- `bucketName`
- `targetPath`
- `acl`

桌面版仅增加最小专用字段：

```json
{
  "infiniteCanvasDesktop": {
    "ramRoleArn": "",
    "stsDurationSeconds": 900,
    "bucketNameOverride": ""
  }
}
```

规则：

- 不新增 `enabled` 配置项。
- 不新增 `region` 配置项，服务端从 `endpoint` 推导。
- `bucketNameOverride` 留空时回退根级 `bucketName`。
- `targetPath` 仍由管理员维护，但桌面版只把它当作根前缀复用，后半段始终固定为 `infinite_canvas/{user_id}/{yyyy}{mm}{dd}/{random}.{ext}`。
- 管理端页面应展示只读路径预览，而不是让管理员继续输入桌面版上传目录。

### 上传时机

当前阶段只上传最终成品图，不上传中间过程图。

## 云端接口建议

建议为桌面版新增独立接口组，不复用网页后台已有登录接口的返回结构。

### 认证接口

- `POST /api/infinite-canvas/auth/login`
- `GET /api/infinite-canvas/auth/me`
- `POST /api/infinite-canvas/auth/refresh`

### 生成控制接口

- `POST /api/infinite-canvas/generation-tickets`
- `GET /api/infinite-canvas/generation-tickets/{ticket_id}/snapshot`

### 任务与日志接口

- `POST /api/infinite-canvas/tasks/{task_id}/events`
- `POST /api/infinite-canvas/tasks/{task_id}/complete`
- `POST /api/infinite-canvas/tasks/{task_id}/fail`
- `GET /api/infinite-canvas/tasks`
- `GET /api/infinite-canvas/tasks/{task_id}/logs`

## 三端交互时序

### 启动与登录

1. Electron 启动。
2. 前端请求云端 `auth/me` 或 `session-status`。
3. 若无有效会话则跳登录页。
4. 用户登录成功后进入在线态。

### 图片生成

1. 用户点击生成。
2. 前端请求云端创建 `generation ticket`。
3. 云端创建 `task` 与 `ticket`。
4. 前端将 `ticket_id` 交给 Go。
5. Go 用 `ticket_id` 请求云端 `snapshot`。
6. Go 获取本次生成的模型配置和 OSS 配置。
7. Go 调上游模型生成图片。
8. Go 上传最终图片到 OSS。
9. Go 回传 `complete` 或 `fail`。
10. 云端写入 PostgreSQL 任务记录与日志。
11. 云端后台可按用户查看最终成品图和日志。

### 禁用账号后的行为

1. 云端禁用账号。
2. 桌面版下一次启动 `auth/me` 失败，进入只读态。
3. 如果桌面版已打开但用户尚未重启，那么下一次点击生成时：
   - 云端拒绝签发 `ticket`
   - 前端提示账号不可生成
   - 桌面版切换为只读态

## 日志与任务记录归属

建议采用“Go 产生日志事件，Python 负责权威落库”的分工。

### Go 负责

- 记录本次生成流程中的关键事件。
- 在关键节点把事件上报云端。

建议事件包括：

- `ticket_snapshot_loaded`
- `generation_started`
- `provider_request_started`
- `provider_request_succeeded`
- `provider_request_failed`
- `oss_upload_started`
- `oss_upload_succeeded`
- `oss_upload_failed`
- `task_completed`
- `task_failed`

### Python 负责

- 校验事件归属是否合法。
- 将事件写入 PostgreSQL。
- 维护任务状态机。
- 给后台页面提供查询能力。

## 对现有 infinite-canvas 的影响

### 前端侧

需要改造：

- 登录入口改为云端登录。
- 启动时先校验云端会话。
- 增加桌面版只读模式状态。
- 生成按钮改为先申请云端票据。

### Go 侧

需要新增：

- 云端客户端模块。
- 票据换快照逻辑。
- OSS 上传模块。
- 任务完成/失败回传模块。
- 过程事件上报模块。

### 本地 SQLite

当前阶段可以继续保留本地数据库与本地缓存，用于桌面版已有数据展示，但不再作为账号、生成权限、云端记录的权威来源。

### 旧链路收口建议

后续建议逐步收掉：

- 本地 Go 直接连外部 PostgreSQL 做登录的临时链路。
- 桌面版本地直连模型的入口。
- 本地持久化长期模型配置和 OSS 配置的逻辑。

## 分阶段实施计划

### 第一阶段：云端基础设施

- 在 `vben-admin-monorepo-template` 中新增桌面版专用数据表。
- 新增桌面版专用登录、票据、快照、任务、日志接口。
- 新增后台页面，按用户查看桌面版生成记录。

### 第二阶段：桌面端登录与只读模式

- 桌面版登录改为云端登录。
- 增加启动时的强在线校验。
- 增加只读模式。
- 禁用账号后阻止继续生成。

### 第三阶段：Go 生成链路改造

- Go 支持用票据拉取快照。
- Go 支持按云端下发的 OSS 配置上传最终图片。
- Go 支持回传任务完成状态和日志。

### 第四阶段：旧逻辑收口

- 关闭旧的本地账号主链路。
- 关闭桌面版本地直连模型能力。
- 将账号、模型和 OSS 配置统一收回云端。

## 风险与边界

### 风险

- Go 当前生成链路若分散在多个服务层，接入票据与快照后需要统一出口。
- 旧本地用户体系与新云端用户体系并存期间，容易出现状态混淆。
- OSS 凭证若直接下发到桌面端，需要严格控制时效和作用域。
- 强在线模式下，云端短时不可用会导致桌面版只能只读，需在产品层面接受这一行为。

### 当前边界

- 当前阶段不接入算力点。
- 当前阶段云端只保存最终成品图，不保存中间过程图。
- 当前阶段桌面版仍保留本地画布与素材缓存，只是不再具备离线生成能力。

## 推荐实施顺序

1. 先在云端 Python 建表与出接口。
2. 再做云端后台“按账号查看最终图片与日志”页面。
3. 然后改桌面前端登录、强在线校验和只读模式。
4. 最后改 Go 接票据、拉快照、上传 OSS、回传记录。

该顺序可以保证每一步都可验证，且能较快获得第一版“云端可控、云端可查”的桌面版闭环。
