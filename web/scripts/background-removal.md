# 离线抠图资源

图片节点的“扣白底图”在独立浏览器 Worker 中使用 IMG.LY 和 ONNX Runtime 推理，不需要 AI API Key。

- `bun run prepare:background-removal` 准备 Worker、模型、WASM、MJS 和许可证；首次准备需要联网下载约 123 MB，后续使用本地文件并校验 SHA-256。
- `dev`、`build` 会先执行资源准备。桌面版沿用 `build:web` 对 `public` 的复制流程，无需另行打包模型。
- 资源生成在 `web/public/background-removal/1.7.0/`，不纳入 Git；运行时只从桌面版本地 HTTP 服务加载，首次抠图也可断网。
- GPU / CPU 统一使用 `isnet_fp16`，避免 `isnet_quint8` 量化模型在浅色图标边缘产生漏扣和孤立碎片。适配器或 `shader-f16` 不可用、初始化失败或推理失败时，销毁 Worker 并使用同一模型在 CPU 上重试。未开启跨源隔离时，ONNX 自动使用单线程 WASM。
- 准备 Worker 时修正 IMG.LY 1.7.0 的透明度转换：使用 `Uint8ClampedArray` 将越界值限制在 0–255，避免整数回绕导致主体破洞、背景杂点；保留正常半透明边缘，不额外腐蚀主体轮廓。
- 推理后以 128/255 提取轮廓，在最长边不超过 1024 的分析蒙版中识别连通区域，移除面积不足最大主体 10% 的独立文字、装饰和碎点，保留规模相近的成组商品。再做闭运算接合细小裂缝，从图像边缘连通识别外部背景，保留封闭区域内的白底、高光和低置信度斑点。外轮廓过渡带使用模型原始连续透明度，RGB 和主体内部透明度始终取自原图。封闭镂空也按主体内部保留，此策略不用于材质透明度估计，也不保证移除与商品相连或面积较大的海报文字。
- 海报外围存在较多小连通区域且主体集中时，按主体边界增加 5% 留白，聚焦该区域再运行一次同一精度模型，减少文字干扰造成的白色包装漏识别；最终仍输出原图尺寸，主体位置不变。纯白底单主体和仅含少量碎点的图片不做第二次推理。
- 成功抠图后在本机 `localStorage` 记录使用的 GPU / CPU 方式；兼容模式成功后，后续直接使用 CPU，刷新或重启后仍保留。取消或失败不记录，升级抠图库版本后重新选择。
- 最多同时处理三张图片，超出后按提交顺序排队；每张独立显示处理状态并支持取消，结束后销毁 Worker 释放模型与显存。结果保持原图尺寸，以透明 PNG 保存到现有浏览器本地图片存储，并新增画布节点。
- 此功能按主体分割背景，不是对白色像素做颜色替换。

库与资源版本固定为 1.7.0，ONNX Runtime 固定为 1.21.0。升级时需同时更新依赖和 `background-removal-types.ts` 的版本，并重新准备资源。分发保留生成目录内的 AGPL 许可证与第三方声明。
